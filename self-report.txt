ЖУРНАЛ РАЗРАБОТКИ (DAILY SCRUM)
===============================

Короткий самоотчёт в начале каждого рабочего дня: что сделано, что планируется,
какие есть препятствия. Записи вносятся по факту.

День 7
------

Что сделано вчера: интерфейс переписан на Qt (PySide6), выпадающие списки и
диалоги лежат внутри окна, тесты интерфейса переписаны под Qt.

План на сегодня: вход и регистрация по макету и удобство ввода:
- проверка формата почты и логина при вводе, вход по логину или почте, красная
  подсветка только того поля, где ошибка;
- галочка «Запомнить это устройство 30 дней»;
- окна входа и регистрации шире, тема операционной системы, плавный градиент;
- единицы измерения везде одним списком, «шт.» по умолчанию;
- кнопка «Добавить товар» открывает окно поверх текущего экрана, карточка товара
  и редактирование так же;
- сортировка по состоянию.

Препятствия:
- ошибку в почте нужно показывать, но не мешать первому вводу. Решение: общая
  проверка полей: ошибка появляется, когда человек ушёл с поля или нажал кнопку,
  дальше поле проверяется на каждой букве.
- при верной почте и неверном пароле краснело и поле логина. Решение: сервис
  возвращает, какое именно поле неверно (login или password), интерфейс
  подсвечивает только его.
- градиент на экране входа не был виден в светлой теме. Решение: для светлой и
  тёмной темы заданы свои доли цвета.

День 8
------

Что сделано вчера: проверка почты и логина при вводе, вход по логину или почте,
«Запомнить это устройство», просторные окна входа, градиент, единицы измерения,
окна товара поверх экрана, сортировка по состоянию.

План на сегодня: таблицы и гибкое окно:
- автоматический масштаб по разрешению и плотности пикселей экрана;
- таблицы аптечки и списка покупок доходят до низа окна, число строк зависит от
  высоты; страницы в списке покупок; подсказки товаров при вводе названия;
- выбор товаров галочками и массовые действия (категория, список покупок,
  удаление), очистка истории;
- окно можно сузить до половины экрана: шапки переносятся, длинный текст
  обрезается, боковую панель сворачивает только пользователь.

Препятствия:
- окно нельзя было сузить: ширина считалась по самому длинному тексту. Решение:
  подписи обрезаются многоточием, шапка из двух частей переносит правую часть
  на вторую строку.
- боковая панель сама пряталась и накрывала содержимое. Решение: её прячет только
  пользователь, содержимое сдвигается и прокручивается.
- Qt запоминает масштаб при первом запуске, временное приложение для измерения
  экрана не подходило. Решение: размер экрана узнаёт короткий отдельный процесс.

День 9
------

Что сделано вчера: автомасштаб, таблицы до низа окна, массовые действия,
очистка истории, гибкое окно и боковая панель.

План на сегодня: настройки, тестовые данные, поиск:
- экран «Настройки»: разделы слева, содержимое справа (внешний вид, уведомления,
  данные, аккаунт, о программе), ручной масштаб, значки меню;
- у имени, логина, почты и пароля отдельные окна изменения, профиль открывается
  по нажатию на аватар;
- полный набор тестовых данных (seed --full), готовая демо-база и демо-сборка
  .exe с тестовым аккаунтом;
- поиск по программе: товары, разделы и настройки, Ctrl+F.

Препятствия:
- ручной масштаб не применялся: значение читалось уже после создания окна.
  Решение: масштаб берётся из настроек до создания QApplication, после выбора
  программа предлагает перезапуск.
- поиск не находил формы слова («витамины» и «Витамин D»). Решение: сравнение
  без учёта регистра, буквы «ё» и окончаний (utils/textmatch).

День 10
-------

Что сделано вчера: экран настроек, окна изменения профиля, тестовые данные,
демо-сборка, поиск по программе.

План на сегодня: правки по итогам просмотра:
- тема устройства, импорт из Excel, крестик в поле поиска;
- порог низкого остатка в настройках уведомлений, числа в подписи сортировки
  по количеству, столбец «Дата добавления», источник позиции списка покупок,
  накопление количества при повторном добавлении;
- списки истории и уведомлений листаются внутри карточки;
- шаблоны CSV и Excel для импорта, поиск по всем разделам.

Препятствия:
- списки истории и уведомлений не уменьшались, когда записей мало: высота
  измерялась, пока виджеты ещё скрыты. Решение: пересчёт высоты сразу после
  перестройки и ещё раз через короткую задержку.
- таблица списка покупок с ограничением CHECK не принимала новые источники, а
  SQLite не умеет менять ограничение. Решение: при запуске таблица пересоздаётся
  с тем же содержимым (миграция), новые базы эту работу пропускают.

День 11
-------

Что сделано вчера: порог низкого остатка, источники покупок, листание внутри
карточки, шаблоны импорта, поиск по всем разделам.

План на сегодня: чистота кода, тесты и шаблон импорта:
- чистка кода по принципам Clean Code: общие основы экранов, общий подвал
  таблицы, помощники дат и поиска, сжатые репозитории (минус около 320 строк);
- тесты: убраны мелкие и косметические, похожие файлы слиты, остались 768 тестов
  с покрытием кода 94 % (coverage.py);
- шаблон Excel на трёх листах: правила, «Моя аптечка», «Список покупок», выпадающие
  списки, рамки и цвет продолжаются сами; импорт из него;
- итог импорта: сколько добавлено в аптечку и в список покупок и причина
  для каждой пропущенной строки.

Препятствия:
- выпадающие списки в Excel были пустыми: ссылка на другой лист не срабатывала.
  Решение: значения записаны прямо в проверку ячейки.
- автопродление таблицы списка покупок брало цвета таблицы аптечки. Решение: у
  каждой таблицы своё правило и свои цвета.
- «Добавлено 0 товаров»: количество в файле превышало допустимый миллион.
  Решение: программа показывает причину и номера строк, лимиты записаны на листе
  «Правила».

День 12
-------

Что сделано вчера: чистка кода, сокращение тестов, шаблон Excel на трёх листах,
подробный итог импорта.

План на сегодня: доводка и документация:
- вход и регистрация не зависят от масштаба пользователя (не меньше 100 %);
- переключатель страниц показывает не больше пяти номеров, кнопка «Очистить
  уведомления»;
- тестовый аккаунт: около 80 товаров, 85 позиций списка покупок, 50 уведомлений
  и 90 записей истории;
- README: установка с .venv, полное руководство пользователя, устранение проблем;
- очистка репозитория от лишнего, облегчено окружение .venv (с 722 до 288 МБ,
  PySide6-Essentials).

Препятствия:
- масштаб Qt меняется только при запуске, а вход должен идти в своём масштабе.
  Решение: после входа и выхода программа перезапускается, вход без пароля
  идёт через запись, которая действует 2 минуты.
- в статистике языков GitHub появился JavaScript из-за одного файла скрипта.
  Решение: файл удалён из main.
- в сообщениях коммитов была лишняя строка соавторства. Решение: история
  переписана и отправлена на GitHub.

Sprint Review (итог этапа, дни 7-12)
------------------------------------

Что удалось показать:
- приложение запускается из виртуального окружения и работает по макету: вход,
  регистрация, главная, аптечка, список покупок, уведомления, история, настройки,
  поиск по программе;
- база SQLite с полным набором операций: добавление, чтение с поиском и
  фильтрами, изменение, удаление (параметризованные запросы, без склейки строк);
- импорт и экспорт Excel и CSV, шаблон для заполнения;
- тестовый аккаунт со всеми видами данных;
- 768 автоматических тестов, покрытие 94 %, black и flake8 без замечаний;
- руководство пользователя и инструкция по запуску в README.

Что не удалось или осталось сделать:
- перенос обновлённых экранов в макет Figma не выполнен;
- Pull Request с комментариями ревью нужно оформить и приложить к отчёту;
- у части методов (около сотни) нет строк документации;
- автоматическая проверка на GitHub Actions не настроена, исполняемый файл нужно
  собрать заново.

Sprint Retrospective
--------------------

Что прошло хорошо:
- слои база - репозитории - сервисы - интерфейс не пришлось менять при смене
  Tkinter на Qt и при новых экранах;
- чистка кода и тесты на каждое изменение быстро находили поломки;
- Feature Branch Workflow и частые коммиты дали понятную историю.

Что можно улучшить:
- собирать шаблоны и тестовые данные скриптами с самого начала, чтобы не править
  файлы вручную;
- проводить Code Review через Pull Request после каждой ветки, а не в конце;
- писать docstrings сразу вместе с кодом, а не после;
- делать резервную копию файла перед любой его правкой;
- планировать день заранее и записывать план в этот журнал до начала работы.
