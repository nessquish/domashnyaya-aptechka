# Менеджер домашней аптечки и запасов

Локальное desktop-приложение на Python (Qt, PySide6) для учёта лекарств, медицинских
товаров, бытовой химии и средств гигиены: сроки годности, остатки, уведомления
и список покупок. Данные хранятся в файле SQLite.

Учебный проект. Разработчик: Сергиенко А. С., группа ИСП-34.

## Быстрый старт

Нужен Python 3.9 или новее (проект проверен на 3.14).

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements-dev.txt
pre-commit install
python -m pharmacy.db.seed
python -m pharmacy
```

Команда `python -m pharmacy` запускает приложение. Для входа под тестовым
пользователем (после `seed`): логин `nessquish`, пароль `demo12345`.

Команда `python -m pharmacy.db.seed` создаёт базу `data/aptechka.db` и наполняет её
тестовыми данными. Ключи:

| Ключ | Что делает |
|---|---|
| `--full` | добавляет данные на все случаи: все состояния товаров, виды истории и уведомлений |
| `--bulk 1000` | добавляет 1000 товаров для проверки скорости |
| `--reset` | удаляет файл базы и создаёт заново |

Готовая база с тестовым аккаунтом (`nessquish`, пароль `demo12345`) лежит в `demo/aptechka_demo.db`.
Чтобы открыть её в программе, скопируйте файл в `data/aptechka.db`. Сроки годности в ней
заданы на день создания, поэтому состояния товаров со временем сдвигаются: свежие
данные всегда даст `python -m pharmacy.db.seed --reset --full`.

## Сборка программы для установки на другой компьютер

Собирается один файл `dist/Aptechka.exe` (около 49 МБ). Python на другом
компьютере не нужен.

```powershell
pip install -r requirements-dev.txt
python packaging/build_exe.py
```

Что важно знать:

- Файл `Aptechka.exe` достаточно скопировать на другой компьютер с Windows 10 или 11
  и запустить двойным нажатием. Установщик не требуется.
- Данные (база и настройки) хранятся в `%LOCALAPPDATA%\Моя аптечка\data`, поэтому
  не пропадают при перемещении или замене `.exe`. Чтобы перенести данные на другой
  компьютер, скопируйте эту папку.
- На новом компьютере база пустая: при первом запуске нужно зарегистрироваться.
- Windows SmartScreen может предупредить о «неизвестном издателе», потому что файл
  не подписан сертификатом. Нужно нажать «Подробнее» и «Выполнить в любом случае».
- Если программа не запустилась, причина записывается в файл `error.log` рядом с базой.

## Структура проекта

Слои соответствуют разделу 2 ТЗ (многослойная архитектура).

| Папка | Назначение | Состояние |
|---|---|---|
| `pharmacy/db/` | схема SQLite, менеджер базы (Database Manager), тестовые данные | готово |
| `pharmacy/models.py` | модели данных: пользователь, товар, категория, уведомление, список покупок, история | готово |
| `pharmacy/errors.py` | ошибки с сообщениями для пользователя | готово |
| `pharmacy/utils/` | хэширование паролей, проверка ввода, даты, форматирование | готово |
| `pharmacy/repositories/` | запросы к таблицам (Repository): пользователи, категории, товары, уведомления, список покупок, история | готово |
| `pharmacy/services/` | бизнес-логика (Service Layer): авторизация, товары, расчёт состояния, уведомления, список покупок, история, настройки, сводка главного экрана | готово |
| `pharmacy/ui/` | интерфейс на Qt (PySide6) по макету Figma: тема, шрифт Inter, виджеты, экраны | готово |
| `tests/` | автоматические тесты (unittest) | готово для всего, что написано |

## Как рассчитывается состояние товара

| Состояние | Условие |
|---|---|
| Просрочен | срок годности раньше сегодняшней даты |
| Скоро истекает | до конца срока осталось не больше N дней (N задаётся в настройках, по умолчанию 30) |
| Низкий остаток | количество не больше минимального |
| Норма | ни одно из условий не выполнено |

У товара может быть сразу несколько состояний. В таблице показывается самое
важное: просрочен, затем скоро истекает, затем низкий остаток.

## Как устроен интерфейс

Интерфейс нарисован только кодом: изображения макета не используются. Он
написан на Qt: окно собирается и рисуется целиком, а на экран попадает готовый
кадр. Поэтому при смене разделов нет мерцания и «квадратов», а переключение
занимает десятки миллисекунд.

- `pharmacy/ui/theme.py` хранит палитры (светлая из макета, тёмная подобрана к ней),
  размеры и стили текста. Других «магических» чисел в виджетах нет.
- `pharmacy/ui/paint.py` рисует скруглённые фигуры и мягкие тени, а
  `pharmacy/ui/icons.py` собирает иконки набора Lucide из описаний контуров
  (SVG, чёткий на экране с любой плотностью пикселей).
- `pharmacy/ui/fonts.py` подключает шрифт Inter из `assets/fonts` (лицензия
  SIL OFL лежит рядом) на время работы программы.
- `pharmacy/ui/widgets/` содержит кнопку, поле ввода, плашку, карточку, таблицу,
  выпадающий список и диалоги. Выпадающие списки и диалоги лежат внутри главного
  окна, а не открываются отдельными окнами.
- `pharmacy/ui/runtime.py` запускает Qt, подключает русский язык стандартных окон
  и рисует значок программы.
- Экраны лежат в `pharmacy/ui/screens/` и обращаются только к сервисам из
  `pharmacy/services/container.py`, не к базе.

Настройки отображения (дополнительно к макету):

- **Размер текста** (в «Настройках», «Оформление»): обычный (в 1,1 раза крупнее
  макета, чтобы мелкий текст читался), средний (в 1,25 раза) и большой (в 1,4
  раза). Применяется сразу. Ширина окна и боковой панели растёт вместе с текстом,
  высота кнопок тоже, чтобы ничего не обрезалось.
- **Боковая панель** сворачивается кнопкой в её заголовке и разворачивается
  кнопкой на узкой полосе слева.
- Эти два выбора запоминаются для каждого пользователя в файле
  `data/preferences.json` рядом с базой. Это настройки внешнего вида, а не данные
  аптечки, поэтому схема базы остаётся строго по ER-диаграмме.
- Тема (светлая и тёмная) переключается в «Настройках» или кнопкой в боковом меню
  и хранится в базе, как в ER-диаграмме.

Размеры совпадают с макетом при любом масштабе Windows: Qt сам пересчитывает
логические пиксели, поэтому окно остаётся резким.

## Уведомления и список покупок

Уведомления строятся из текущего состояния товаров и пересчитываются при
добавлении или изменении товара, при смене настроек и при входе:

- причина появилась: создаётся непрочитанное уведомление;
- текст изменился (например, остаток): текст обновляется, отметка «прочитано»
  сохраняется;
- причина исчезла (срок продлён, запас пополнен): уведомление удаляется;
- уведомление «Срок истёк» и «Низкий остаток» можно отключить в настройках,
  «Скоро истекает» зависит только от числа дней предупреждения.

Удалённое вручную уведомление вернётся, пока причина не устранена.

В список покупок позицию можно добавить вручную или из товара (например,
из уведомления о низком остатке). Количество по умолчанию докупает запас до
двойного минимального остатка. Покупка отмечается в списке и записывается
в историю, остаток в аптечке пользователь меняет сам через форму товара.

## Соответствие ER-диаграмме

В ER-диаграмме ТЗ имена русские, в коде английские.

| ER-диаграмма | Таблица | Основные поля |
|---|---|---|
| Пользователи | `users` | `login`, `username`, `email`, `password_hash`, `warning_days`, `theme`, `notify_expired`, `notify_low_stock`, `created_at` |
| Категории | `categories` | `name` |
| Товары | `products` | `user_id`, `category_id`, `name`, `quantity`, `unit`, `expiry_date`, `indications`, `storage_place`, `min_quantity`, `note`, `created_at` |
| Уведомления | `notifications` | `user_id`, `product_id`, `kind`, `message`, `is_read`, `created_at` |
| Список покупок | `shopping_list` | `user_id`, `product_id`, `name`, `quantity`, `unit`, `source`, `is_bought`, `created_at` |
| История | `history` | `user_id`, `product_id`, `action`, `description`, `created_at` |

Правила удаления: при удалении пользователя все его данные удаляются каскадно.
При удалении товара его уведомления удаляются, а в истории и списке покупок
ссылка на товар обнуляется (`ON DELETE SET NULL`), сами записи остаются.
