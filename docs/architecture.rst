Архитектура
===========

Приложение разделено на четыре слоя. Зависимости идут только сверху вниз:
интерфейс не обращается к базе напрямую.

.. code-block:: text

   ui            окна Qt, экраны, виджеты, тема
    |
   services      бизнес-правила, проверка данных, транзакции
    |
   repositories  параметризованные SQL-запросы к таблицам
    |
   db            менеджер базы Database, схема SQLite

Сквозные модули: ``models`` (модели данных), ``errors`` (ошибки с понятным
пользователю текстом), ``utils`` (даты, проверка ввода, пароли, единицы),
``config`` (путь к базе), ``crashlog`` (журнал аварий).

Использованные шаблоны
----------------------

* **Database Manager**: единая точка доступа к SQLite и транзакциям.
* **Repository**: отдельный класс запросов на каждую таблицу.
* **Service Layer**: бизнес-правила; каждое действие записывается в историю
  в той же транзакции, что и изменение данных.
* **Контейнер сервисов** (``services.container``): единая точка получения сервисов.
* Разделение, близкое к **MVP**: экран отвечает за вид и реакции, сервис за правила.

Структура пакетов
-----------------

* ``pharmacy/db``: схема (``schema.py``), менеджер базы (``connection.py``), тестовые данные.
* ``pharmacy/repositories``: запросы к таблицам users, categories, products,
  notifications, shopping_list, history.
* ``pharmacy/services``: сервисы авторизации, товаров, уведомлений, списка
  покупок, истории, настроек, сводки главной и импорта/экспорта.
* ``pharmacy/ui``: тема, виджеты и экраны.
* ``tests``: автоматические тесты unittest.
* ``packaging``: сборка исполняемого файла PyInstaller.

База данных
-----------

Шесть таблиц: ``users``, ``categories``, ``products``, ``notifications``,
``shopping_list``, ``history``; первичные и внешние ключи, ограничения CHECK,
UNIQUE, каскадное удаление и пять индексов. Все запросы выполняются с параметрами
«?»; поле сортировки берётся из фиксированного списка.
